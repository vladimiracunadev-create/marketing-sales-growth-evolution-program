# Proyecto transversal — Ruta Andina SpA

## Propósito

Diseñar, validar, lanzar, comercializar y optimizar una oferta centrada en el cliente sin crear un segundo
caso conductor. Cada entrega reutiliza evidencia previa; si una decisión cambia, se conserva la versión
anterior y se registra qué evidencia motivó el cambio.

## Reglas de evidencia

- Separa `dato / inferencia / hipótesis / decisión`.
- Usa datos sintéticos o anonimizados; no subas información personal o comercial sensible a servicios externos.
- Declara fuente, fecha, responsable, límite y criterio de revisión.
- Una salida de IA es un borrador: debe incluir validación humana y alternativa sin IA.
- Las piezas posteriores enlazan el identificador de la evidencia que reutilizan; no copian conclusiones sin contexto.

## Puertas de revisión

1. **Cliente y problema (1–9):** no avanzar si la persona sigue siendo enteramente hipotética.
2. **Valor y economía (10–17):** no avanzar si valor, precio, costo de servir y margen se contradicen.
3. **Producto y validación (18–22):** no construir más fidelidad de la necesaria para resolver la hipótesis.
4. **Mercado y operación (23–29):** no lanzar si ventas, implementación, soporte, datos o cumplimiento no están listos.
5. **Defensa y aprendizaje (30):** no ocultar resultados negativos; un abandono oportuno bien sustentado es evidencia de competencia.
